# nb-recrawl learnings

## 2026-09-14/15 (initial build)
- Many developer sites return 406 without full browser Accept/Accept-Language headers (e.g. 4acapital.am).
- Map referrer: images from ar-go.am and similar block hotlinking with a Referer — the web app sends no-referrer.
- Dedupe pitfalls: same building across sources with Armenian vs Latin titles; different buildings with shared street name. Curated merges live in scraper/merge_overrides.json (by source URL) — add new confirmed groups there instead of loosening thresholds.
- Titles in ALL-CAPS Armenian are transliterated at build time (build_dataset.latinize_names).
- Open-Meteo elevation rate-limits (429): elevation.py backs off; re-run build to fill gaps.

## 2026-11-06 (fresh recrawl of all sources)
- Result: 664 → 691 projects; 46 added, 18 removed (all delisted at source), 8 price changes (none > 40 %), 6 stage changes, 3 pins moved (max 768 m real). Report: scraper/reports/diff-20261106-1753.md (diff-20261106-1751 is the superseded first pass).
- Homebrew `python3` is now 3.15 without `shapely`; `build_dataset.py` (via geo_admin) fails with ModuleNotFoundError. Run the pipeline with `python3.14` (or 3.12), which has shapely 2.1.
- construction.am: LiteSpeed reCAPTCHA "Bot Verification" on every page (registry → blocked). The old fetch cached the 2 KB captcha page as if it were content; extra_sources.py now refuses to cache it and carries a source's previous records forward when it returns 0, so one broken source no longer wipes 132 projects.
- dignisi.am: sitemap.xml became a sitemap index (scraper follows children) and the redesign put whitespace between tags, which silently nulled status and handover for all 75 records (showed up as ~20 "→ unknown" stage changes). Check field coverage per source, not just record counts.
- ar-go.am: new status label "սպասվում է" → planned.
- devsites agents: batch membership changed between runs, and one agent dropped charagayt.am (18 ML Mining records) and pallada.am believing another batch covered them. Compare per-domain counts old vs new across all batch files before building; resume the agent for any domain that went to 0.
- Duplicates surfaced when a second developer (contractor/seller) lists the same building: promgroup/metruminvest Eden Park, renshin/artlife Kempinski (Teryan 107), spitaktnak/sophene Aghbyur Serob 26 → merge_overrides. Park Royal gained coordinates and got auto-merged into Pallada (~300 m) → "separate" override. goghtvalley.com's buildings page pins east of Yerevan → geo_overrides to Goght village.
- Diff artefact: acba.am uses one generic URL (mortgage-loans/8979) for several projects, so the URL-keyed diff may pair unrelated projects (Vv8 "moved 1936 m" was a mismatch, not a move).
- Agents: 3 batches, ~13–25 min each; new projects found 8 / 12 / 5 per batch; 6 developer sites dead or repurposed (heartofyerevan.com, arcsisrealty.com, layeghvard.am DNS, hayview.am now a news blog, sil.am timeout, shem.am is a TV site).
- Build bug fixed during the follow-up verify: a source URL inherits its project ID from git HEAD, and an ID match skipped the "separate" check, so a wrong merge committed once could never be undone. The build now re-IDs the record whose ID came from another source when the two are kept apart. A "separate" group keeps EVERY listed URL apart pairwise, so don't list two URLs of the same project in it (pallada.am + kp/6).
- ID stability (build_dataset.py): a merge survivor with a fresh ID adopts the HEAD ID of a merged record, unless the survivor is a kp-<n> record or a curated survivor_id. HEAD's merged_ids are carried forward. Check: rebuilding right after a commit should leave the ID set identical to HEAD, apart from source order in multi-source records.
- ID reuse (found 2026-11-07): from the 2026-10-15 build, three myhome IDs (884, 889, 892) whose projects had been absorbed elsewhere were handed to new buildings. September's verdicts then moved those buildings onto the old sites (Zard 15 → Kapan, NovaVan Tumanyan 14 → Milon B district, Micro-district 318 → MIDIS Park). Fixes: the stale entries were retired (id "…~retired" + note); new IDs are now numbered above every ID in a verdict/fix file (verdict_ids()); scraper/dropped_ids.json remembers URL→ID for projects removed by "not a project"/"remove", which beats HEAD, so removed records stay removed (Yeraz, White Island and Avan project had resurfaced). Audit after a build: verdict entries whose title shares nothing with the project their ID resolves to.
- 2026-11-08 push: site CI failed. Five local data commits had skipped the site bookkeeping (`npm run archive/slugs/lastmod`), so 34 project IDs from the deployed dataset were neither live nor archived. 9 of them were drift, not removals. The recrawl commit (d1b2ec1, before the ID-stability fix) had re-ID'd TM Tower, Noy, NARMARK, Dalan Technopark, Vv8, Park Royal (URL /hy/home → /en) and three redgroup → redinvest projects, which also orphaned their September verdicts. Fixed by renaming the IDs back in projects.json plus the Nov verdict files, committing, and rebuilding. The other 25 were archived from git history, since HEAD no longer held them. Check before pushing: compare live IDs against the last pushed commit (`origin/<branch>`), not only HEAD; a new ID carrying an old project's source URL is drift.
